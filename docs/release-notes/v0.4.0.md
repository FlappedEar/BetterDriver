Alpha 0.4.0: 2.7K·60 phone video asks the encoder for 60 fps and the report checks the frame rate (FBBD-246, FBBD-247), and no "best yet" praise from a corner driven while cooling down (FBBD-244).

What changes for the driver:
- Phone video at 2.7K·60 now tells the video encoder to run at 60 fps. In 0.3.43 a 2.7K·60 file held 48.4 fps: the camera ran at 59.5 fps, but about one frame in five never reached the file (FBBD-246). The cause is inferred, with medium confidence; the next 2.7K log confirms it.
- The session report has a new **Video frame rate** row for each phone camera: frames in the file over its length, against the set rate. It passes at 95 % of the set rate or more (57 fps at 60). Stored reports are made again in the new format.
- The report made when recording stops now waits for the last phone video file to close (up to 8 s). Before, it ran before a 2.7K file closed and showed a false video-coverage FAIL (FBBD-247).
- The log line written as each 2.7K file closes adds frames the camera failed, buffers lost, sensor frames skipped, and whether the file has sound.
- A corner taken while cooling down, or lifted off for traffic, no longer earns a "best yet" praise. Before, such a pass could still queue a praise that was then said on the next lap.
- Lap timing is unchanged from 0.3.43.
