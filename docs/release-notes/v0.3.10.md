Alpha 0.3.10: correctness fixes from review of the 0.3.8 and 0.3.9 work, consistent names across screens, and no crash when a session cannot be analysed. No new features. This is the build for the next drive, which checks the RaceBox link and phone video start fixes from 0.3.9 (FBBD-218).

What changes for the driver:
- **A session that cannot be analysed no longer crashes the app (FBBD-219).** The screen says "This session could not be analysed" and the error goes to the diagnostic log.
- **Consistent names (FBBD-219).** Best actual lap, raw theoretical best and realistic optimal are named the same on every screen. A corner's passes open as "Every pass" from every entry point. "Where time goes" rows show the lap that set each corner's best as "lap N", not "best lap N". Lap lists read the same in the summary and the optimal video, and an empty realistic optimal says why ("No compatible combination of laps" or "Needs every corner timed"). The RaceBox live screen is "RaceBox diagnostics", car data is "Car data (OBD-II)" everywhere, and track lengths always use a decimal point.
- **Corner corrections (FBBD-179).** A shared track whose only correction is a moved corner boundary is no longer treated as already present, and taking it moves the boundary. Names and chicanes kept across a layout change keep the track marked as corrected, so Restore automatic stays available and sharing carries them. A damaged revision history can no longer make corner lookup loop forever.
- **Progression (FBBD-181).** Its session limits count only the track's own sessions, so older sessions at a track are reached even with many newer sessions elsewhere. A session skipped while a backup restore started is tried again on the next open.
- **Next-session focus and coaching history (FBBD-20, FBBD-180).** Straights are not listed as corners left out of the plan. A corner left out for weak evidence is marked withheld in the history instead of "no longer a top-three loss". The session the coach worked from is found even when the phone clock put it later.
- **Laps and corners (FBBD-215).** Lap start and end points are interpolated with the GPS gap floor, and smoothing keeps a point-to-point run's start and finish in place.
- **Driving states and corner passes (FBBD-175, FBBD-93).** A brake channel in bar or psi is no longer read as a pedal. Distance covered twice after a GPS gap counts once, so coasting is not inflated. The approach to a corner just after the line is read from the previous lap. The speed range on corner passes uses High-confidence passes only. A corner opened from progression on a session that fails to load shows "unavailable" instead of spinning.
