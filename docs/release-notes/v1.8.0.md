1.8.0: the phone's own GPS can be a session's receiver when there is no RaceBox (FBBD-275), live G and RPM are smoothed like RaceChrono's (FBBD-302, FBBD-303), and the fixes from the 22 October audit (FBBD-287..301, 304).

What changes for the driver:
- Phone GPS is added under Settings › Devices › Add equipment › Add without Bluetooth (UI-153 B). A session with it records the phone's positions (about one a second), with Android's accuracy estimate; lap times and confidence treat them as phone positions, and the 25 Hz receiver checks do not apply to them. If Android refuses location at the start, the app asks again every 10 s.
- The G tile on the track screen averages each axis over the last 0.5 s before combining them, so it no longer jumps with every bump.
- Engine RPM and the other OBD and heart-rate tiles show the mean of the last 0.3 s instead of a single reading. VBO exports draw a straight line between OBD readings up to 1 s apart, as RaceChrono does; wider gaps hold the last value.
- A lap with a GNSS gap still shows its time but is never the best lap, the delta reference or a coach reference. Live timing, replay and analysis use one gap rule (3 median intervals, at least 0.5 s; 3 s for phone GPS).
- Bluetooth links pass on notifications only from the current connection, so no old bytes arrive after a reconnect.
- A stop that the writer has not finished keeps the session active until it has; a Start in that time is ignored. The camera service waits up to 90 s for the video to be finished, and a stuck video writer ends its file with "writer stalled" instead of filling memory.
- Damaged MP4, GoPro GPMF and .bdsession files are refused with an error instead of crashing or using huge amounts of memory. GoPro imports survive the app being killed; track saves no longer overwrite each other.
- The lap review reads a session again when its files changed.
