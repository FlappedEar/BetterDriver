1.6.4: 1080p · 60 records through the app's own encoder, which hands each frame's buffer back at once, and the log times every step from camera to file (FBBD-278).

What changes for the driver:
- 1080p · 60 on the phone now records through the app's own Camera2 and encoder path (as 2.7K did) instead of CameraX's recorder. Each encoded frame is copied and its buffer handed back to the encoder at once; a separate thread writes the MP4. Until now the write came first, under the lock shared with sound, so a slow write could hold the encoder and, through it, the camera. If the own path cannot start, 1080p · 60 records with CameraX as before.
- A new log line once a minute, "encoder timing", gives per frame the time from the frame to the encoder's callback, how long the encoder's buffer was held, the wait for the writer and for the lock, and the time in writeSampleData, so a delay shows where it arises. The file line's encode_ms now ends at the encoder's callback; it used to include the write.
- The "camera frames" line also counts Camera2 frame numbers with no result (frame_numbers_missing), apart from skipped sensor timestamps.
- The log names any camera result value that switches partway through a file ("camera result switched" lines, from a snapshot every 10 s) and lists the camera's vendor request and result keys once.
- Nothing changes on screen. Files are MP4 (H.264 and AAC) as before.
